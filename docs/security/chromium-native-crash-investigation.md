# Native Chromium window-creation investigation

Status: unresolved. This investigation does not assert a fix or change the existing native shutdown code. Existing Windows x64 runs [41056133471](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/41056133471), [41058414944](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/41058414944) and [41180385222](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/41180385222) reported `FATAL ui\\gfx\\win\\hwnd_util.cc:65` with Windows error 87 in the native browser test around the rapid tab-creation/close sequence, after the last-tab replacement check. Error 87 means invalid parameter, but the failing argument, stack, window ownership and root cause are not established. A later passing run is not proof of a fix.

## Reproduction and evidence to collect

On an isolated x64 Windows test runner, build the exact revision and run the existing native browser test repeatedly using its documented workflow; retain the rapid tab-close and popup assertions. Record attempt count, OS build, CEF/CefSharp build, architecture, exit code, last completed assertion and sanitized CEF log. A test-only trace should correlate UI thread, form/tab/browser IDs, create and dispose events, native HWND creation/destruction and timestamp, without URLs, cookies, profile data or credentials. Collect Windows Error Reporting/Event Viewer details and native stacks or dumps only when configured and permitted for synthetic profiles; review artifacts for secrets before publishing. No dump has yet established the cause.

The separate `hwnd-repro` mode in `AegisBrowser.BrowserTests` exercises a smaller candidate sequence five times: create a synthetic form, replace its last tab, rapidly create four tabs, and request close twice. It logs relative time, managed thread, control type and native handle creation/destruction. It does not reproduce the original renderer-crash and popup setup, so a pass does not rule out a dependency on those steps. The Windows workflow runs this mode alongside, not in place of, the existing full test; no assertions or shutdown ordering were removed. Run it manually only with a new disposable profile root: `AegisBrowser.BrowserTests.exe hwnd-repro <synthetic-root>`. Review any native logs or crash dumps before sharing. The revised trace requires another Windows x64 run.

The smaller sequence reproduced the fatal error on its first cycle in [Windows x64 run 41263009521](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/41263009521), commit `4eb8d4e1f01c3c5b7befd9b0dc12b21e0fa924c6`. The trace recorded a `BrowserView` handle created and then destroyed while tab pages were being removed, shortly before `hwnd_util.cc:65` error 87. This establishes a reproducible candidate without the preceding renderer crash or popup, but does not establish which parent or native call failed. Tab selection during teardown is a hypothesis to test, not a proven cause.

On the Windows ARM64 development host (build 26300), an offline-built x64 CEF test reached all five cycle completion messages and its CEF shutdown marker without the reported HWND failure. The process exit code was not captured reliably. Chromium also reported that Windows encryption was unavailable in this sandboxed synthetic profile (error 2), so this is neither session-persistence nor full ARM64 compatibility acceptance. The cause of that encryption error is unverified. Repeated runs, the original full sequence and a native dump are still needed.

Inspect `MainForm` tab replacement and form close ordering, `BrowserView` native host release, popup lifetime, UI-thread dispatch, browser initialization and subprocess exit. Separate facts from hypotheses: timing, handle ownership, disposal and resource limits are candidates, not conclusions. Do not add arbitrary sleeps, suppress assertions, skip the test, or change native release ordering to manufacture a pass. Reproduce on a clean Windows x64 runner and separately on Windows 11 ARM64 with x64 CEF emulation; x64 CI does not establish ARM64 behavior. Any evidence-backed fix belongs in a separate reviewable PR with repeated failure/recovery and shutdown tests.
