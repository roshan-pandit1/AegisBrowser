# P4-FP-05: isolated OffscreenCanvas WebGL engine research

## Revision and evidence boundary

The research branch starts at PR #68, `feature/p4-fp-04-worker-webgl-protection`, commit `61a4f9cf0931faa59d99c0714543753880d1ff31`. Production uses .NET 8, CefSharp.WinForms.NETCore 154.0.340, CEF 154.0.34 and Chromium 154.0.8037.98. The pinned CEF commit is `14c5a089e8452874cb1a556dc3fde26ed2d87723`.

At that exact CEF commit, [CHROMIUM_BUILD_COMPATIBILITY.txt](https://raw.githubusercontent.com/chromiumembedded/cef/14c5a089e8452874cb1a556dc3fde26ed2d87723/CHROMIUM_BUILD_COMPATIBILITY.txt) specifies `refs/tags/154.0.8037.98`. The Chromium mirror's [tag reference](https://api.github.com/repos/chromium/chromium/git/ref/tags/154.0.8037.98) resolves directly to commit `b859317bf11f6be47f9b7799ec690a0a42a1fb33`. This establishes the source metadata mapping; it is not independent provenance verification of a produced binary or a claim that the entire Chromium dependency checkout is present.

The stock CEF runtime is the baseline. No stock-runtime observation is a patched-engine result. Parent evidence and new baseline observations are recorded separately from any source proposal. A source patch, even if it applies cleanly, is not a compiled engine, a demonstrated sandboxed runtime, or a CefSharp-compatible distribution.

## Existing policy and source boundary

Production runs one leased profile per application process, checks incomplete profile transactions and calls `ProxyRepository.EnsureRuntimeReady` before `Cef.Initialize`. `DisableWebGl` is profile-local and default off. It supplies CEF `IBrowserSettings.WebGl = Disabled` before an ordinary browser host is created; its documented recovery is to disable it and restart the profile. CEF's [renderer preference mapping](https://github.com/chromiumembedded/cef/blob/14c5a089e8452874cb1a556dc3fde26ed2d87723/libcef/browser/prefs/renderer_prefs.cc) maps the setting into document WebPreferences for WebGL 1 and 2. Chromium's [HTMLCanvasElement checks](https://github.com/chromium/chromium/blob/b859317bf11f6be47f9b7799ec690a0a42a1fb33/third_party/blink/renderer/core/html/canvas/html_canvas_element.cc) consult frame settings. Its [OffscreenCanvas host](https://github.com/chromium/chromium/blob/b859317bf11f6be47f9b7799ec690a0a42a1fb33/third_party/blink/renderer/core/offscreencanvas/offscreen_canvas.h) instead returns true for the two WebGL enablement checks and false for its blocked check. [WebGL context creation](https://github.com/chromium/chromium/blob/b859317bf11f6be47f9b7799ec690a0a42a1fb33/third_party/blink/renderer/modules/webgl/webgl_rendering_context_base.cc) consults those host checks.

This difference applies to a document-created OffscreenCanvas as well as a worker-created one. The parent [push](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/43023636578) and [PR](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/43023645369) Windows x64 workflows passed. Their controlled positive baselines created WebGL 1 and 2; HTMLCanvas was unavailable under the tested restriction while document and dedicated-worker OffscreenCanvas WebGL 1/2 remained functional. Two source-documented process switches were tried only in disposable test processes and did not close that gap. This does not establish that all possible engine mechanisms are ineffective.

## Candidate policy propagation and limitations

A candidate internal model is a default-preserving WebGL 1/2 enablement snapshot scoped to the execution context rather than a mutable process-global variable. For an applicable document, OffscreenCanvas could consult the owning frame's existing settings. For a dedicated worker, pinned [`DedicatedWorker::CreateGlobalScopeCreationParams`](https://github.com/chromium/chromium/blob/b859317bf11f6be47f9b7799ec690a0a42a1fb33/third_party/blink/renderer/core/workers/dedicated_worker.cc#L510-L546) constructs `WorkerSettings` from its parent frame settings; nested dedicated workers copy their parent's snapshot. [`WorkerSettings`](https://github.com/chromium/chromium/blob/b859317bf11f6be47f9b7799ec690a0a42a1fb33/third_party/blink/renderer/core/workers/worker_settings.h) currently contains only a subset of settings and no WebGL fields. [`WorkerGlobalScope`](https://github.com/chromium/chromium/blob/b859317bf11f6be47f9b7799ec690a0a42a1fb33/third_party/blink/renderer/core/workers/worker_global_scope.cc#L777) takes the creation-parameter settings.

This is a design direction, not a completed or reviewed policy contract. Shared workers may have multiple clients with different policies, service workers can outlive documents, and neither may safely borrow an arbitrary client's settings. Cross-origin frames, process reuse, policy changes after worker creation, detached or destroyed contexts, and popup ownership require explicit semantics. The [OffscreenCanvas deserializer](https://github.com/chromium/chromium/blob/b859317bf11f6be47f9b7799ec690a0a42a1fb33/third_party/blink/renderer/bindings/core/v8/serialization/v8_script_value_deserializer.cc#L748-L765) recreates a transferred canvas from the receiving script state; transfer between contexts with different policies therefore needs an explicit rule and negative tests. A dedicated-worker snapshot alone does not prove per-profile isolation or a safe policy for all worker types.

Any future engine implementation must leave default behavior unchanged, reject WebGL 1/2 only when an applicable explicit policy requires it, retain Canvas 2D, and avoid modifying WebGPU, GPU identities, TLS, sandbox, proxy routing or permissions. If a worker lacks a valid scope, its handling must be decided and reviewed explicitly rather than defaulting into a false protection claim. CEF/CefSharp compatibility and policy activation remain separate integration contracts.

## Source-only prototype

The [research patch](../research/chromium-webgl-policy/0001-prototype-offscreen-context-settings.patch) adds a default-off experimental Blink feature and a proposed web test. Under that guard, document OffscreenCanvas consults the receiving frame's WebGL settings; dedicated workers use WebGL 1/2 settings copied at worker creation, including nested-worker copies. Missing or uninitialized dedicated-worker settings deny WebGL under the experimental guard; the existing alternate `WorkerSettings` constructor leaves these new fields false, and that route needs explicit compatibility tests. The patch intentionally leaves shared and service workers unchanged, and does not solve transfer into a differently configured receiving context. The guard is not wired to production AegisBrowser and the candidate must not be treated as a complete isolation boundary.

Five source files fetched at the exact Chromium commit were independently compared with the upstream mirror and checked against the [manifest](../research/chromium-webgl-policy/source-manifest.json). On that subset, `verify_source_subset.py` reported matching SHA-256 values and `git apply --check --whitespace=error-all` passed. Modified-source and nested-Git-root negative controls were rejected. This verifies only those inputs and patch applicability, not a complete checkout, compilation, generated test APIs, Blink tests, security isolation, or CEF compatibility. The proposed web test includes WebGL 1/2 positive controls and document, dedicated/nested worker, same-policy transfer and 2D cases; all remain **NOT_RUN**.

## Build feasibility

The pinned Chromium [Windows build instructions](https://raw.githubusercontent.com/chromium/chromium/b859317bf11f6be47f9b7799ec690a0a42a1fb33/docs/windows_build_instructions.md) call for an x86-64 machine, at least 100 GB of free NTFS storage, a supported complete Visual Studio 2026 installation and Windows SDK 10.0.28000.2270. They also describe x64 debugger requirements for ARM64 Windows hosts. CEF's [build guide](https://chromiumembedded.github.io/cef/branches_and_building.html) describes the separate CEF source/build process. A Windows x64 output is not established merely because an ARM64 host can run an x64 .NET application under emulation.

Read-only local checks observed an ARM64 Windows host, two logical CPUs, approximately 35.6 GiB free on C: and 6 GiB installed RAM (via Windows memory APIs), Windows SDK include directory `10.0.26100.0`, and Visual Studio Build Tools 18 reported incomplete and not launchable by `vswhere`. `gn`, `ninja`, and `depot_tools` were not found on PATH; Python 3.15.2 and the x64 .NET 8 SDK were present. These observations do not authorize changing host security settings or installing tooling. The pinned full Chromium/CEF build was not run on this host.

An eventual disposable build must verify both source commits and the actual dependency revisions, provision the pinned instructions' prerequisites, apply any reviewed patch with `git apply --check` before application, generate an isolated x64 GN output directory, and compile the smallest owning test targets discovered with `gn refs`/`gn ls` before building an experimental CEF distribution. Record exact commands, environment, patch hash and output hashes. CEF's automated builder may replace its source directory, so patches must be retained separately and application verified. No experimental binary may be copied into the production release as part of this research.

## Verification and production status

The stock CEF fixture was rerun locally in separate write and restart/read processes on Windows ARM64 under x64 emulation. Each completed 128 checks with exit code 0 and returned from CEF shutdown. Baseline WebGL 1/2 and Canvas 2D were functional; the enabled per-browser setting blocked HTMLCanvas WebGL in the controlled documents and native popup, while document-created and dedicated-worker OffscreenCanvas WebGL 1/2 remained functional. WebGPU adapter requests were inconclusive. These are stock-runtime results, not patched-engine results.

The source-only prototype and subset checks are not a completed enforcement implementation. At source-prototype commit `dc705bb533db268fed459b09444bbb81538f0031`, the Windows x64 stock-runtime [push](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/43072499461) and [PR](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/43072570022) workflows passed, as did the independent source-subset [push](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/43072500731) and [PR](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/43072570069) checks. These workflows did not build or run the patched engine. Patched Chromium compilation, Blink tests and patched-runtime CEF/CefSharp compatibility are **NOT_RUN** until real compatible artifacts and outputs exist. WebGPU adapter observations cannot be inferred from WebGL; patched-engine Canvas 2D behavior and profile/popup isolation must be independently tested. Preserve the existing OffscreenCanvas warning.

Production integration is **NOT_STARTED**, experimental engine readiness **NOT_APPROVED**, and full fingerprint resistance **NOT_ESTABLISHED**. No engine patch changes should weaken the sandbox, TLS, permissions, required-proxy guard, or native popup ownership, and no JavaScript API overrides or fabricated GPU identities are acceptable.
