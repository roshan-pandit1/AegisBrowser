# P4-FP-09: SOCKS callback reliability

This test-harness change starts from draft PR [#72](https://github.com/roshan-pandit1/AegisBrowser/pull/72), commit `0812a828cb17d15c0cdb50e5f4ee788f088ca058`. The application remains pinned to .NET 8, CefSharp 154.0.340, CEF 154.0.34 and Chromium 154.0.8037.98. No production proxy routing is enabled.

## Historical behavior and baseline

In the parent PR's [final-head PR workflow, attempt 1](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/43187922876/attempts/1), one stopped-listener SOCKS navigation entered loading but had no matching load error within 25 seconds. Only after the test requested browser close did the callback report `Aborted`; the other concurrent process observed `ProxyConnectionFailed`. Browser and CEF shutdown were reported, with zero trace events dropped. [Attempt 2](https://github.com/roshan-pandit1/AegisBrowser/actions/runs/43187922876/attempts/2) passed. The retry does not establish the original cause.

Before these edits, the parent native fixture was run on Windows ARM64 under x64 emulation. One single-process run passed 31 proxy checks, exited 0 and reported CEF shutdown; the offline callback was `ProxyConnectionFailed`, and the separate deliberate stop produced `Aborted`. One concurrent pair also passed with two distinct test-owned processes, exit 0 each, and reported CEF shutdown. These three process observations do not establish that the intermittent timeout is resolved.

An intermediate P4-FP-09 concurrent pair reproduced the stopped-listener timeout in **both** test processes. Each entered loading, timed out at approximately 25 seconds, and observed `Aborted` only after its browser-close request; each reported browser closure and CEF shutdown, with zero dropped trace events. The observer preserved each final outcome as `TimedOut`. Both processes exited as failures. These intermediate runs had not yet reached the separate rejection scenario; their GPU-cache path warnings and concurrent timing do not establish a cause for the missing callback. Logs remain in the ignored disposable `artifacts/fp09-concurrent-v1` directory on the test host. The original stopped-listener scenario remains required and is not replaced by the protocol-rejection scenario.

## Executable changes

The new test-owned navigation observer correlates main-frame outcomes with the expected controlled URL. It distinguishes network errors, explicit cancellation, unsolicited `Aborted`, success, timeout and browser close, and counts wrong-navigation, duplicate, late and contradictory events. Synthetic negative cases exercise those distinctions, including a callback racing the timeout-recording lock. A timeout or close cannot be converted to an observed network failure by a later `Aborted` callback. This observer does not expose a Chromium navigation identifier and does not prove complete network-event coverage.

The fixture additionally offers a separate SOCKS5 CONNECT rejection for one test-owned loopback destination. It sends `VER=5`, `REP=2` (ruleset denial), `RSV=0`, IPv4 zero bound address and port, as specified for SOCKS5 replies in [RFC 1928 section 6](https://www.rfc-editor.org/rfc/rfc1928#section-6). It records the reply was sent and checks Chromium's resulting error and terminal loading. A separate direct TCP positive control proves the local origin was listening, and the rejected navigation is checked against that origin's request log. The test-only proxy configuration removes Chromium's implicit loopback bypass for this case; it does not change application networking. This is bounded evidence for one controlled request and does not establish system-wide containment.

The original stopped-listener path is still tested separately with its 25-second deadline and requires a matching non-cancellation `LoadError`; a TCP control confirms the stopped listener independently refuses a new loopback connection at that moment. The released port is not reserved after this check, so the test does not prove that no other process could bind it before Chromium's navigation. A deliberately held SOCKS request is canceled only after the fixture observes it and must report `Aborted`. Neither a protocol denial nor a close-triggered cancellation is treated as evidence that a stopped listener reliably produces an immediate error. `LoadingStateChanged(false)` is browser-wide and provides supplementary settling evidence; the terminal network error must match the main-frame URL.

The concurrent launcher continues to run two processes and check both exit codes. On timeout or an early launch failure it now attempts bounded termination of the test-owned root processes whose handles it retained, and still classifies a timeout as failure. A synthetic child-process test exercises cleanup without killing its independent sibling, and checks that the actual launcher rejects unexpectedly exiting non-CEF peers. Forced termination is not a normal CEF shutdown, and root-process cleanup alone does not prove all native descendants terminated. A local edit initially introduced a PowerShell syntax error in the expanded test; it was corrected and both checks then passed.

## Observed post-change result and limits

The final local single-process CEF run passed 47 proxy checks, exited 0 and reported normal CEF shutdown. The SOCKS server logged `SOCKS_REJECTION_SENT`; Chromium reported `SocksConnectionFailed`, and the independently reachable origin did not observe the rejected navigation. The stopped-listener path reported `ProxyConnectionFailed`, and the deliberate cancellation reported `Aborted`. Its native trace had zero dropped events. This is one bounded local observation; repeat and hosted results must be recorded separately.

An optional fail-fast stress run of the pre-final observer revision reached 20 sequential test profiles: all 20 retained logs contain the required success, stopped-listener error, explicit denial, no-direct-origin, cancellation and normal CEF-shutdown markers with zero dropped trace events. Reaching the twentieth iteration establishes that the driver's exit checks accepted the first 19; the outer driver's output was lost with its session, so the twentieth process exit code and final summary were not retained. A separate single run using the updated driver persisted exit 0 and its summary. The driver now records per-run results and a summary in its disposable log directory. These stress results preceded the final timeout-race correction.

A separate fail-fast concurrent stress run passed its first pair and stopped on the second: one process exited 0, while the other timed out after its direct TCP control had confirmed connection refusal. The failed process emitted `Aborted` after close and reported CEF shutdown. Both processes had already sent explicit denial replies and reported `SocksConnectionFailed`. An earlier intermediate pair also timed out in both processes. Thus the 20-pair diagnostic target was not completed; these failures are not counted as successes or automatically retried.

The intermediate failure and earlier hosted failures show that the stopped-listener callback timeout is reproducible in available runs, but do **not** establish its cause. The explicit protocol-denial case supplies a separately testable failure mode and stronger outcome classification; it does not fix or explain the missing stopped-listener callback. No result here proves a general absence of direct traffic, operating-system containment, or proxy safety for production profiles.

In the PR run, the single native probe passed 47 checks and reported normal browser/CEF shutdown with zero dropped events. Both concurrent child processes also passed 47 checks, exited 0 and reported browser/CEF shutdown with zero dropped events. Each observed the explicit denial, no controlled-origin request, stopped-listener network error and deliberate cancellation. This is bounded evidence, not proof that the historical intermittent timeout is fixed. See the draft PR checks for the latest commit.

Any native failure, timeout or missing callback remains a failure; no automatic retry is part of the fixture. Preserve the original failed attempt when reporting any later successful run. Production CefSharp pins, sandboxing, TLS validation, popup ownership, user profiles and `ProxyRepository.EnsureRuntimeReady` remain unchanged. The local .NET builds succeeded with `NU1900` warnings because vulnerability metadata was unreachable; one concurrent build attempt collided on an intermediate file and failed before a later serialized build passed.
