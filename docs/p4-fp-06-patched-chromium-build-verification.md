# P4-FP-06: Patched Chromium build verification

## Starting point and scope

This research starts from draft PR [#69](https://github.com/roshan-pandit1/AegisBrowser/pull/69), `feature/p4-fp-05-isolated-engine-webgl-policy`, commit `54e7679c4ad1fba5a8077a7929fc100fd82774c1`. The pinned application uses .NET 8 and CefSharp 154.0.340, with CEF 154.0.34 at `14c5a089e8452874cb1a556dc3fde26ed2d87723` and Chromium 154.0.8037.98 at `b859317bf11f6be47f9b7799ec690a0a42a1fb33`. CEF's [pinned compatibility file](https://raw.githubusercontent.com/chromiumembedded/cef/14c5a089e8452874cb1a556dc3fde26ed2d87723/CHROMIUM_BUILD_COMPATIBILITY.txt) identifies the Chromium version tag; the parent investigation recorded the matching mirror commit. Mapping a release tag to source metadata does not verify the provenance of a compiled binary.

The existing [P4-FP-05 report](p4-fp-05-chromium-offscreen-webgl-engine.md) identifies why the CEF per-browser document preference does not cover OffscreenCanvas. The stock CEF fixture observed WebGL 1 and 2 in a dedicated-worker OffscreenCanvas despite the active browser setting. That observation is distinct from behavior of a patched engine.

## Builder qualification

Read-only qualification of the development host found Windows ARM64, two logical CPUs, approximately 6 GiB installed RAM and 34.99 GiB free NTFS space at measurement. The available Windows SDK was 10.0.26100.0; a complete Visual Studio workload, depot_tools, GN and Ninja suitable for the pinned build were not established. Resource values are time-dependent. The [pinned Chromium Windows build instructions](https://github.com/chromium/chromium/blob/b859317bf11f6be47f9b7799ec690a0a42a1fb33/docs/windows_build_instructions.md) call for an x86-64 machine, at least 8 GB RAM, at least 100 GB free NTFS storage, a compatible Visual Studio installation and the required SDK/tools. This host was not qualified for the full build.

[GitHub's standard hosted Windows runner specification](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job) lists 4 CPUs, 16 GB RAM and 14 GB SSD storage for public repositories. The listed storage is below the pinned Chromium guide's 100 GB free-space requirement, regardless of CPU or memory. A read-only authenticated query of this repository's self-hosted runner inventory returned zero registered repository runners; that result does not enumerate other organizations or independent builders. No suitable additional authorized disposable Windows x64 builder has been established. No paid machine was provisioned and no host security settings, drivers or user files were changed.

## Source, patch and compilation

The existing [source manifest](../research/chromium-webgl-policy/source-manifest.json) pins CEF and Chromium revisions, the source subset and patch digest. Its verifier checks source and patch SHA-256 values, requires the selected root to be a Git repository top level, and checks patch applicability; the corresponding negative test rejects modified input and nested Git roots. These are source-subset checks only. The source subset is not a full Chromium checkout, has no synchronized DEPS, and cannot compile the engine.

The P4-FP-06 [checkout qualifier](../research/chromium-webgl-policy/qualify_chromium_checkout.py) adds a read-only gate for a future checkout: it requires the pinned main-repository commit, a non-shallow repository, expected source markers, gclient metadata and a clean tracked/nonignored main working tree before running the subset verifier. Seven local synthetic Git-fixture tests passed, covering wrong revisions, dirty and untracked files, nested roots, missing markers and metadata, shallow clones and unborn repositories. The existing five-file subset was correctly rejected as incomplete. These checks do not establish synchronized dependency revisions, toolchain suitability, ignored-file integrity or executable behavior. The [evidence manifest](../research/chromium-webgl-policy/build-verification.json) records absent engine steps as `NOT_RUN`.

The current [prototype](../research/chromium-webgl-policy/0001-prototype-offscreen-context-settings.patch) introduces a default-off experimental gate. The proposed behavior consults receiving-document WebGL settings or a dedicated worker's `WorkerSettings` snapshot; nested workers copy the snapshot. Proposed tests include document, dedicated/nested worker, same-policy transfer and Canvas 2D cases with positive controls. Neither those tests nor generated Blink APIs have been established by a build. Check applicability, discover the owning GN targets and record actual compiler/test results on the exact full checkout before treating the patch as executable evidence.

A separate [incremental source candidate](../research/chromium-webgl-policy/0002-prototype-worker-settings-presence.patch) records whether worker settings are known and preserves that state in copied snapshots. Its proposed gate continues to deny an unknown snapshot while the experimental feature is enabled; this is not a reviewed ownership contract. It applies after the original patch on a disposable verified five-file subset, but has not been compiled. No unregistered C++ test was added. Registration and execution must be established from the full checkout. The [policy audit](../research/chromium-webgl-policy/p4fp06-policy-audit.md) describes the remaining transfer and ownership gaps.

No patched Chromium compilation, Blink test discovery or Blink test execution has been completed as part of this report. `PATCH_COMPILATION`, `BLINK_TEST_DISCOVERY`, and `BLINK_TEST_EXECUTION` remain **NOT_RUN**. No CEF binary was built, and CefSharp binding compatibility remains incomplete. Record any subsequent verified source, patch, builder, GN arguments, target, build output and artifact hashes in the research evidence manifest; absent observations remain `NOT_RUN`.

The stock AegisBrowser browser-test project built locally for Release win-x64 with exit code 0. NuGet vulnerability metadata could not be reached, including on a subsequent network-enabled attempt; the build used the available restored packages and emitted `NU1900` warnings. This is a stock-browser build, not a Chromium build.

On the ARM64 workstation under x64 emulation, the stock `fingerprint-write` probe passed 128 checks, exited 0 and reported completed CEF shutdown. Its positive controls created WebGL 1 and 2 contexts in HTMLCanvas and in document and dedicated-worker OffscreenCanvas. With the existing browser setting enabled, tested HTMLCanvas contexts were unavailable in the main document, same-origin and cross-origin frames, and native popup; document and dedicated-worker OffscreenCanvas WebGL 1 and 2 remained functional. Canvas 2D was functional. This reproduces the stock-runtime gap and does not test either source patch.

## Worker policy and isolation limitations

The prototype is not yet a reviewed policy for all execution contexts. Its alternate `WorkerSettings` construction path and missing-settings behavior require explicit tests; a default-initialized value must not silently stand in for an independently established security policy. Worker creation, nested copying, termination and recreation also require actual execution.

An OffscreenCanvas transfer is evaluated by the prototype in the receiving execution context. Transfers between differently configured contexts, destruction of the original owner and already initialized contexts require a defined ownership contract and independent tests. A restrictive receiver must not be bypassed by an object created elsewhere, and a permissive receiver must not be presumed entitled to discard source restrictions. Shared workers may serve clients with conflicting settings; service workers may outlive a document. Neither can safely inherit an arbitrary client's policy without a reviewed model. OOPIFs, renderer reuse, profile separation and native popup behavior likewise remain unverified.

The proposed patch does not intend to alter Canvas 2D or WebGPU, but intention is not a compatibility measurement. Stock-runtime Canvas 2D observations do not establish patched-engine compatibility; WebGPU adapter results remain inconclusive. No global GPU restriction, JavaScript monkey-patch or synthetic device identity is introduced.

## Security and next action

Production integration has not started. The existing production CefSharp pins, CEF binaries, Chromium sandbox, TLS checks, origin permissions, profile leases, popup ownership and `ProxyRepository.EnsureRuntimeReady` guard remain unchanged. Required-proxy profiles must stay blocked before CEF initialization while network containment remains unverified. The existing OffscreenCanvas warning remains in place.

The next independently executable step is to obtain an authorized, disposable Windows x64 builder meeting the exact pinned toolchain and storage requirements; verify the complete checkout and DEPS; use GN target discovery; then compile and run the smallest relevant Blink tests with WebGL 1/2 positive controls. Preserve exact commands, logs and build/test exit codes. A successful source check or stock CI run is not a patched-engine result, a compatible CEF build, or production readiness.
