# Host feasibility for the isolated Chromium experiment

This is a read-only assessment of the development host on 2026-11-11. No Chromium checkout, engine build, toolchain installation, or disk cleanup was attempted as part of this assessment. The application continues to use its existing stock CEF runtime.

| Resource | Observation | Meaning |
| --- | --- | --- |
| Host | Windows 10.0.26300, ARM64 OS and ARM64 PowerShell process; 2 logical processors | Native architecture differs from the requested Windows x64 target. The existing application tests can run under x64 emulation; that is not evidence that a Chromium build is supported. |
| RAM | `GetPhysicallyInstalledSystemMemory` returned 6.00 GiB; `GlobalMemoryStatusEx` returned 5.99 GiB total and about 2.18 GiB available at measurement | Below the pinned build guide's 8 GB minimum. Availability is time-dependent. |
| Storage | C: is NTFS, 118.95 GiB total and 35.61 GiB available at the latest measurement | Below the pinned build guide's 100 GB free-space minimum. Do not delete other worktrees or user files to create space. |
| Visual Studio | VS 18 BuildTools files exist, including MSVC 14.51.36231 and `MSBuild\Current\Bin\MSBuild.exe`; `vswhere -all -format json` returned an empty list in the sandbox | File presence is not proof that the required Visual Studio workload, ATL/MFC, or pinned Chromium toolchain is complete. |
| Windows SDK | `Include\10.0.26100.0` is present; `Windows Kits\10\Debuggers\x64` is absent | The pinned guide calls for SDK 10.0.28000.2270 and calls out x64 debugging tools on ARM64. |
| Other tools | ARM64 Git 2.56.0.windows.4, Python 3.15.2 and x64 .NET SDK 8.0.427 are available. `gn`, `ninja`, `gclient`, `fetch`, `clang-cl`, `cmake`, `cl` and `msbuild` were not on the default PATH. MSVC includes `Hostarm64\x64\cl.exe` and `Hostx64\x64\cl.exe`. | A file existing outside PATH does not establish a configured Chromium environment. Chromium's pinned LLVM/depot_tools and exact tool revisions remain unverified. |

Measurements used `[System.Runtime.InteropServices.RuntimeInformation]::OSArchitecture`, `ProcessArchitecture`, `[Environment]::ProcessorCount`, `[Environment]::OSVersion.VersionString`, and `[System.IO.DriveInfo]` for C: `DriveFormat`, `AvailableFreeSpace`, and `TotalSize`. Memory was queried through the read-only Windows `GetPhysicallyInstalledSystemMemory` and `GlobalMemoryStatusEx` APIs. Tool discovery used `Get-Command` and read-only `Get-ChildItem` on the Visual Studio and Windows Kits directories. The `Get-CimInstance Win32_OperatingSystem` query was denied in the sandbox; the memory result above does not depend on CIM.

The official [Chromium 154 Windows build instructions](https://raw.githubusercontent.com/chromium/chromium/154.0.8037.98/docs/windows_build_instructions.md) describe the checkout and build process and list an x86-64 machine with at least 8 GB RAM, at least 100 GB of free NTFS storage, Visual Studio 2026 with required C++ components, and the corresponding Windows SDK. Their ARM64 note also identifies an x64 debugger dependency. The guide is a build prerequisite reference, not a verification that this host meets the full exact-revision toolchain requirements.

The measured RAM and free disk alone preclude a responsible full pinned Chromium checkout and build here. The smallest suitable next environment is an isolated Windows x64 builder with adequate storage and memory, the pinned source and tool revisions, and a verified compatible Visual Studio/SDK installation. First compile and run the smallest relevant Blink tests there, then consider an experimental CEF build; do not place generated artifacts in the production browser. These steps have not been run, and their outcome is not assumed. Ordinary hosted Windows x64 AegisBrowser CI remains a separate stock-runtime regression track.
